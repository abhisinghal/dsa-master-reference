Google's L4–L6 interviews emphasize **DP**, **Graph algorithms**, **Backtracking**, and **Divide & Conquer** — with sharp attention to **correctness proofs** and **complexity analysis**.

## What Google looks for by level

| Level | Focus |
|---|---|
| **L3 (SWE)** | Arrays, strings, hashing, tree traversal |
| **L4 (SWE II)** | Medium DP, BFS/DFS, sorting-based problems |
| **L5 (Senior)** | Hard DP, tricky graph, algorithm + design trade-off |
| **L6 (Staff)** | Hard algorithm + system + review-others' code |

## What Google interviewers care about

- **Correctness proof** — can you argue *why* your algorithm works, not just what it does?
- **Tight complexity** — Google interviewers push for the theoretically optimal bound.
- **Code quality** — variable naming, function decomposition, no dead code.
- **Follow-up scaling** — "What if n = 10⁹?"
